# Feature Specification: Magpie 安全开源与社区接入准备

**Feature Branch**: `main`（本次无分支钩子，未创建或切换分支）

**Created**: 2026-11-10

**Status**: Draft

**Input**: User description: "将现有 Magpie KOReader 插件整理为不泄漏个人密钥或配置的开源项目；README 支持中英文并包含 Feature / Install / Usage / Dev；使用 subagent worker 收集信息，考虑接入 KOReader 社区。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 维护者安全公开项目 (Priority: P1)

维护者能从个人项目中整理出独立、可再分发的插件，确认公开内容不包含自己的凭据、私人配置或个人内容。

**Why this priority**: 一旦公开，删除当前文件无法撤回已传播的信息；公开边界必须先明确。

**Independent Test**: 在不访问维护者私人环境的条件下检查候选公开仓库、拟公开历史和分发材料，确认所有发现均已处置，示例仅含虚构数据。

**Acceptance Scenarios**:

1. **Given** 插件来自包含个人配置的工作环境，**When** 维护者准备公开候选版本，**Then** 所有拟公开文件、历史、附件、截图、日志和分发包均纳入检查，真实凭据及私人配置值均不出现在公开材料中。
2. **Given** 内容依赖私人服务或个人数据，**When** 外部用户获取项目，**Then** 用户能够区分插件自带能力与需要自行提供的服务及数据，且不会默认连接维护者的私人服务。
3. **Given** 检查发现敏感内容或再分发权利不明，**When** 维护者评估发布，**Then** 该候选版本不能被标记为可公开，处置记录只描述类别与位置而不复制敏感值。

---

### User Story 2 - 中英文用户独立安装与使用 (Priority: P2)

中文和英文用户分别从 README 进入，理解插件用途、前置条件与支持边界，并完成安装、配置和首次使用。

**Why this priority**: 开源交付必须让不认识维护者的用户也能使用。

**Independent Test**: 中文、英文各一名验证者仅凭对应语言的说明，在满足已声明条件的环境中完成安装、启动和一个已支持的使用流程。

**Acceptance Scenarios**:

1. **Given** 用户只阅读一种语言，**When** 打开对应 README，**Then** 能找到 Feature、Install、Usage、Dev 四部分和另一语言入口，关键步骤与限制不存在语言差异。
2. **Given** 用户已满足所列前置条件并提供自己的必要配置，**When** 按安装与使用说明操作，**Then** 插件可被发现、启动，并完成文档描述的首个使用流程。
3. **Given** 用户未提供必要配置、服务不可达或内容为空，**When** 尝试使用相关功能，**Then** 获得可执行的说明，不暴露凭据，也不把不可用内容误示为成功结果。
4. **Given** 用户需要升级或移除插件，**When** 按文档操作，**Then** 能预先知道个人配置与数据如何保留或移除。

---

### User Story 3 - 外部开发者贡献与社区发现 (Priority: P3)

外部开发者能理解项目边界、验证修改并提交贡献；维护者拥有有来源依据的社区接入路径和可供审阅的介绍材料。

**Why this priority**: 社区接入依赖可维护的独立项目、准确说明和符合目标社区要求的材料。

**Independent Test**: 一名未参与原项目的开发者依照 Dev 完成一次修改验证；维护者按目标社区的公开要求逐项核对提交材料。

**Acceptance Scenarios**:

1. **Given** 开发者没有维护者的私人服务或账号，**When** 阅读 Dev 与贡献说明，**Then** 能了解开发前置条件、验证方法、问题反馈与贡献路径，并区分可独立验证和需要自备服务的部分。
2. **Given** 维护者准备向社区介绍项目，**When** 查看接入资料，**Then** 至少有一条可执行的推荐路径，附一手来源、核验日期、需要的材料与尚未满足的条件。
3. **Given** 社区有自动索引、人工精选或不同分发方式，**When** 描述支持情况，**Then** 明确区分已验证兼容、待验证和仅供参考，不把准备好材料写成已被收录。

### Edge Cases

- 被忽略或未跟踪的本地文件仍可能进入分发包；公开检查不能只看当前跟踪文件。
- 敏感值曾进入拟公开历史，但当前文件已经删除；历史仍必须检查并处理。
- 截图、示例内容、日志或错误信息含有个人信息；与代码采用同一公开边界。
- 原来源的许可或第三方素材授权不明确；在权利确认前不宣布可再分发。
- 新安装没有配置，或仅配置部分功能；不可依赖维护者机器上的默认值才能启动。
- 用户没有外部内容服务、网络不可用或内容为空；明确说明受影响的功能和恢复步骤。
- 文档两种语言不同步，或社区规则发生变化；标明验证依据并在交付前核对差异。
- 只有部分设备经过验证；不把 KOReader 插件身份等同于全设备兼容。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 项目 MUST 明确独立交付边界，列出保留的用户能力、外部服务依赖及不包含的原项目部分；为每项保留能力定义至少一个可观察的使用验收流程。
- **FR-002**: 所有拟公开材料 MUST 不包含维护者真实密钥、访问令牌、密码、私人服务地址、个人账号或设备标识、个人业务数据及私人配置值；检查范围包括候选仓库当前内容、拟公开历史、示例、文档、图片、日志、附件和分发包。公开的项目名称、作者署名与上游链接不属于私人配置。
- **FR-003**: 项目 MUST 提供可安全公开的配置说明与虚构示例，明确必要项、可选项及取得方式；用户能使用自己的配置，且私人配置不被默认纳入公开材料。
- **FR-004**: 插件 MUST 在缺少私人环境时仍可被安装并进入其使用入口；需要额外配置或服务的功能必须给出可执行提示，不得默认使用维护者凭据或服务。
- **FR-005**: 项目 MUST 提供互相可发现的中文和英文 README；两种语言均包含 Feature、Install、Usage、Dev，且功能、限制、前置条件、步骤和安全说明语义一致。
- **FR-006**: Feature MUST 区分实际提供、依赖外部服务及未支持的能力，并列出已验证设备或运行环境以及未验证范围，不将灵感项目的能力当作本项目能力。
- **FR-007**: Install 与 Usage MUST 覆盖获取插件、安装位置、启用或重启、个人配置、首次成功使用、常见失败、升级和卸载及其对个人数据的影响；按文档操作不得要求维护者私下补充信息。
- **FR-008**: Dev MUST 说明开发前置条件、独立验证方式、需要自备服务的验证边界、贡献流程及问题报告需要的信息，并提醒报告者排除敏感信息。
- **FR-009**: 项目 MUST 具有明确的开源许可及必要的来源和第三方许可说明；在宣布可公开前确认维护者有权分发包含的内容。
- **FR-010**: 项目 MUST 提供社区接入评估，覆盖插件索引、精选清单、官方贡献仓库及用户列举的两类设备内商店；重要结论附一手来源与核验日期，未知项明确标注。
- **FR-011**: 社区评估 MUST 推荐至少一条可执行的接入路径，并准备项目介绍、用途分类、公开项目入口、安装指引及该路径要求的其他材料；不以社区接受或实际收录作为交付前提。
- **FR-012**: 发布准备 MUST 留存脱敏检查结论、能力验收结果、双语文档核对结果、许可状态和未解决问题；敏感发现或权利问题未解决时不得标记为可公开。

### Key Entities

- **公开候选版本**: 拟向外部交付的插件、文档、历史与分发材料，以及对应的验证状态。
- **用户配置**: 由使用者自行提供的连接、认证与偏好信息；与可公开虚构示例区分。
- **功能与依赖清单**: 用户能力、使用前提、外部依赖、支持边界及验收流程的对应关系。
- **双语说明**: 中文、英文两套语义一致的功能、安装、使用与开发入口。
- **社区接入资料**: 目标渠道、依据、核验日期、接入条件、材料和状态。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% 拟公开材料类别均有检查记录；未解决的敏感内容发现为 0，未解决的再分发权利问题为 0。
- **SC-002**: 中文、英文 README 的四个必需部分覆盖率均为 100%；关键步骤、限制和前置条件的未解决语义差异为 0。
- **SC-003**: 中文、英文各至少一名未参与整理的验证者，在满足文档前置条件后，仅凭对应语言文档于 30 分钟内完成安装、启动和首次成功使用，无需维护者补充私人信息。
- **SC-004**: 已声明保留的功能均至少通过一个实际使用验收流程；缺失配置、不可达服务和空内容三类场景均有可理解且不泄漏敏感值的结果。
- **SC-005**: 至少一名外部开发者能够按 Dev 在 60 分钟内完成文档指定的本地修改验证；需要自备服务的验证被明确列出，不以维护者私有环境作为隐含前提。
- **SC-006**: 社区评估覆盖 5 个指定渠道，至少一条推荐路径的所需材料齐全；“已收录”或“已兼容”等无证据声明为 0。

## Assumptions


### 已收集的产品依据与边界

- 源码 worker 静态确认现有能力为：今日用量与配额、按项目费用、在飞项目及详情、今日/七日/三十日趋势、手动和定时刷新。开源整理默认保留这些能力；不将其重新定位为通用知识卡片系统。依据：原插件 `main.lua`、`office.lua`、`projcost.lua`、`dashview.lua`。
- 数据来自独立的 Magpie gateway 与 web 服务；在飞视图还依赖对应的办公室页面服务。插件仓库不包含这些服务，其可获得性和自建条件须在规划中核实并如实写入文档。
- 静态调查发现内置部署地址、密钥持久化、截图或会话标题泄漏的风险类别；公开材料检查必须覆盖这些位置。调查未读取真实密钥，也未执行安装或联网验证。
- 当前源码对凭据传输与保存存在需要评估的限制；文档不得宣称凭据只存在外部文件、所有连接均安全验证或凭据权限只读。现有实现细节与修复方案留给规划，不在本规格中指定。
- 未找到可确认的原项目许可证；FR-009 的权利检查是公开前置条件。静态源码证据不等同于设备兼容性或安全验收通过。
- 本功能是现有插件的安全开源整理，不新增用户列举的 AI、RSS、同步、天气、阅读统计或首页替换能力；这些项目仅作为社区定位与交互参考。
- 本次命令产出规格及质量清单；实际迁移、文档编写、发布验证属于后续实施。不会在本次命令公开仓库、推送代码或向社区提交消息。
- 目标读者已拥有可运行 KOReader 的设备或验证环境；完整外部服务实现不默认纳入插件仓库，但必须公开足够的依赖与配置说明以消除私人知识依赖。
- 中英文支持指 README 内容，不自动扩展为插件界面的双语改造。
- 开源许可的具体选型将在规划阶段基于来源权利确认；规格要求明确且可再分发的许可，不提前假定原代码已有可用许可。
- 默认不搬运无必要的原项目历史；若选择公开任何历史，该历史同样必须满足 FR-002。
- 社区规则以核验时的一手资料为准；插件数量、热度和第三方收录结果不是本功能验收指标。
- 当前项目 constitution 是未填写模板，不能据此推导额外产品约束。

### 社区调查结论

- 两个 worker 的脱敏调查与一手来源汇总见 [research.md](research.md)，核验日期为 2026-11-10；其中静态调查和社区文档阅读均不构成安装兼容性证明。
- 推荐先准备可被社区发现的独立项目，再准备 Awesome KOReader 的人工精选提交材料；官方 contrib 作为后续可选路径。该推荐不代表已经发布、提交或获准收录。
- 插件索引与两类商店均存在按公开项目标记或命名发现项目的机制；索引发现、精选收录与实际安装兼容是三个独立结果。依据：[plugin-index](https://github.com/omer-faruq/koreader-plugin-index/blob/main/README.md)、[AppStore](https://github.com/omer-faruq/appstore.koplugin/blob/main/README.md)、[Storefront](https://github.com/ultimatejimmy/storefront.koplugin/blob/main/README.md)。
- 精选清单要求公开项目、用途与安装说明、兼容性信息及作者身份披露；contrib 要求可工作的上游项目和功能说明。依据：[Awesome 贡献说明](https://github.com/jannick-holm/awesome-koreader/blob/main/CONTRIBUTING.md)、[contrib 开发者要求](https://github.com/koreader/contrib/blob/main/README.md)。
